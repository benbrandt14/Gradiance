# Arrays, rebuilt — the decision
Phase T (arrays) · roadmap § "Unified plan" · status: ready (after Phase H)

Written by the planning thread, 2026-11-21. Owner: arrays were "a failed attempt before, but it's a high value feature and good to spend time on with a good reference" (`docs/vectorcraft-survey.md` rows 17-19). Docs and one review question; no code.

## Goal

A successor to `docs/array-decision.md`, written after studying
VectorCraft's Repeat end to end, that answers:

1. **Why the first attempt failed.** Read the removed per-copy tween code in
   git history (the "Deliberately small" module doc of
   `crates/gradiance-command/src/array_cmd.rs` names it)
   and say which part was untrustworthy: the tween maths, the ghost, the
   pitch, or the interaction.
2. **The model.** Baked bodies only (today), or a **recipe** — an authored
   `ArraySpec` on the group (kind, count, spacing, radius, angle span,
   centre, axis) whose copies are real bodies regenerated by one command when
   the recipe is edited, until a copy is edited on its own (then the link
   bakes). Session best estimate: the recipe, because VectorCraft's value is
   the on-canvas handles on an *existing* repeat, and Adjust Last (U-11)
   only reaches the last operation.
3. **What a copy may differ by.** Rule proposed: each copy is a **rigid
   transform** of the source (translation, rotation, reflection via N-9's
   structural mirror). No size tweens (that is T-5's blend, a separate
   operation). Joints *between* source members are copied; joints to
   outside bodies are not.
4. **The handles.** VectorCraft's count handle, radius handle, ring
   splitter, spacing sliders and mirror axis, mapped onto Gradiance's
   select-tool handles without clashing with the Ctrl-drag array gesture.
5. **Physics.** Copies are created paused; a recipe edit while playing
   pauses and records (feel invariant 6).
